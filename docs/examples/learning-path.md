# 04｜动手练习路线

这条路线从前端已经熟悉的 HTTP 请求开始，逐步练习后端的参数绑定、业务分层、数据查询、权限和错误诊断。每一关都说明它解决的问题、实际操作和完成标准。建议先静态读代码，再用本地或隔离的开发环境验证；开始前用 `git status` 确认工作区，涉及 SQL、共享服务或外部数据源时先确认目标环境。

## 学习工具与记录方式

准备好浏览器 Network、IDE 全局搜索、服务日志和一张调用链草图。每次练习记录四项：观察到的事实、对应源码位置、验证方法、还不确定的环境条件。这样能把“猜测接口应该如此”变成可复现的结论。

可按如下模板记一条请求：

~~~text
页面动作：
前端 API 函数：
完整浏览器 URL / HTTP method：
请求参数位置：
Gateway 路由：
Controller / DTO：
Service 业务规则：
Mapper / 下游服务：
原始响应 / 前端最终拿到的对象：
权限与错误分支：
~~~

## 第 1 关：画出接口路径

**要解决的问题：** 前端调用的是相对 URL，后端 Controller 也只声明服务内部路径；不弄清 baseURL、网关前缀和类/方法映射，很容易把 404 当成后端方法不存在。

**怎么做：** 从 `datacenter-web/src/api/componentList/index.js` 的 `componentListQry` 开始，找页面调用处和 `request.js`。分别记下 API wrapper 的 `url`、Axios `baseURL`、浏览器 Network 中的完整 URL，以及 `DashboardPageController` 的类级和方法级映射。最后查当前环境 Gateway/Nacos 路由如何重写路径。

**检查问题：**

- `params` 从页面哪个状态产生，发送后显示在 URL 的哪个位置？
- 页面 API 文件中的路径是否含有 Gateway 前缀？
- Controller 类级路径与方法级路径拼成什么服务内路径？
- 浏览器请求为什么还可能包含服务内路径之外的前缀？

**完成标准：** 画出“页面 → API wrapper → Axios → Gateway → Controller”的路径图，并明确哪些内容来自代码、哪些需要环境配置才能确认。

## 第 2 关：解释响应结构

**要解决的问题：** HTTP 200 只说明传输层成功；业务 code 可能失败，拦截器还可能解包响应，因此页面看到的对象不一定等于服务端原始 JSON。

**怎么做：** 在 Network 保存一次脱敏后的列表响应；找到 Controller 返回类型 `MixinsResp`、分页对象 `PageVO` 及 `request.js` 响应拦截器。对照原始 JSON、拦截器的返回值和页面变量，分别标出 HTTP status、业务 code/message、data、分页字段。

**完成标准：** 能说清页面变量是完整响应还是 `res.data`，并解释 HTTP 401/403/500 与业务错误码分别在哪一层处理。不要把 Token、用户数据或真实业务响应复制进知识库。

## 第 3 关：追分页查询与数据模型

**要解决的问题：** 筛选条件如果只在页面处理，会导致分页总数不准、跨页面规则不一致；如果 DTO、数据库实体和返回对象混在一起，还可能让调用方控制内部字段或收到不必要的数据。

**怎么做：** 按 `DashboardPageController.page` → `DashboardPageServiceImpl.getByCategory` → `IDashboardPageDao` → `PageEntity` 的顺序阅读。给 `DashboardSearchDTO` 的每个字段标注来源、默认值和是否参与查询；在 Service 中找到筛选、排序、分页逻辑；确认返回的 VO 是否与 Entity 相同。

**完成标准：** 画出一个筛选字段从页面状态到查询条件的流向，并能解释页码起始值、每页条数、total 和稳定排序。新增可选筛选字段时，说明旧客户端不传该字段为何仍可工作。

## 第 4 关：追图表数据配置

**要解决的问题：** 图表不是简单地按一个 ID 查表；页面配置、图表配置、数据集和运行时参数需要正确关联，同时数据库连接与 SQL 不应暴露给浏览器。

**怎么做：** 从 `getChatInfo` 追到 `ChartDataController`，检查 `ChartDataSearchDTO`、`PageEntity.config`、`BasePageDTOTypeHandler`、`DashboardPageDTO.chartList` 和 `BaseChartDataService`。标出 `pageCode` 如何定位页面、`chartCode` 如何定位图表、图表配置如何指向数据集，以及最终如何生成 `ChartDataVO`。

**完成标准：** 不看 UI 也能描述配置查找和数据查询顺序；遇到空图表时可以区分“没有匹配配置”“数据集返回空”“异常被转换为空响应”等不同原因，并知道应该查哪一段日志。

## 第 5 关：区分认证、授权和数据范围

**要解决的问题：** 隐藏按钮只能改善界面体验，不能阻止用户直接构造 HTTP 请求；即使用户有菜单权限，也不代表他能读取所有记录。

**怎么做：** 检查前端路由守卫、按钮权限指令、请求拦截器携带 Token 的方式，再检查 Controller/安全组件上的服务端鉴权和数据范围条件。记录身份凭证在哪生成、在哪验证、角色或权限码在哪判断、数据范围在哪收窄。

**完成标准：** 能分别解释认证（确认是谁）、授权（允许做什么）和数据权限（允许访问哪些记录），并根据响应和日志初步区分 401、403 与“成功但空结果”。如果某个接口没有显式注解，也要继续检查全局过滤器、拦截器或网关规则，不能直接认定它没有保护。

## 第 6 关：做一个向后兼容的小改动

**要解决的问题：** 接口字段经常逐步演进；直接改必填字段或字段含义可能让旧页面、其他调用方和已部署服务互不兼容。

**怎么做：** 在个人分支给列表查询增加一个可选筛选字段，按 DTO → Service 查询条件 → 前端 API 参数 → 页面控件的顺序改动。先确认旧请求不带字段时的默认行为，再为新旧两种请求分别验证。优先使用 Mock、测试替身或本地数据，不要未经确认连接共享数据库。

**完成标准：** 旧请求结果保持原有语义，新字段能改变预期筛选结果，非法字段值有可理解的错误反馈；接口文档、测试和调用方同步更新。

## 第 7 关：验证业务行为并说明证据

**要解决的问题：** 代码能够编译不代表业务规则正确；只断言方法被调用，也无法证明边界条件或返回值符合约定。

**怎么做：** 选择一个有清晰业务规则的 Service 方法，覆盖成功、无数据、无权限或非法参数等最重要路径。若问题发生在 HTTP 参数绑定或权限过滤，再补 Controller/Web 层测试。运行项目规定的检查命令，并记录未启动的外部依赖。

**完成标准：** 测试断言输入与可观察结果之间的关系；提交说明写清触发条件、行为变化、运行过的命令和仍未覆盖的环境条件。不要把“编译成功”描述成“生产接口验证通过”。

## 每次读代码都可以问的问题

1. 用户做了什么动作，哪段页面代码发起请求？
2. 参数从页面哪个状态来，最终位于 URL、JSON body 还是 FormData？
3. Axios、Gateway 和认证组件分别改变或检查了什么？
4. 哪个 Controller 接收请求，DTO 如何校验？
5. 业务规则在哪个 Service，哪些 Mapper/Feign Client/数据集执行器被调用？
6. 哪些异常直接返回错误，哪些被降级成空列表或默认对象？
7. 返回模型如何序列化，前端拦截器如何解包？
8. 是否有事务、缓存、数据权限、日志脱敏或幂等要求？
