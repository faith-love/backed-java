# 工程与分布式：把代码变成可运行、可协作的服务

这一部分回答三个问题：**代码怎样构建和交付？服务怎样被浏览器访问？多个服务怎样在网络失败和消息重复的情况下协作？** 作为前端开发者，可以从一个接口请求开始，沿着浏览器、代理、网关、业务服务、消息和数据库逐层找证据。

## 推荐学习顺序

1. 先看 [Git](./git.md)、[Maven](./maven.md) 和 [Docker](./docker.md)，理解代码如何协作、构建并进入容器。
2. 再看 [CI/CD 与可靠发布](./cicd.md)，理解测试、制品、环境晋级、部署验收和回滚如何连接。
3. 再看 [Linux](./linux.md)、[Nginx](./nginx.md) 和 [部署总览](./operations.md)，区分构建、发布、启动、健康检查和验收。
4. 通过 [计算机网络基础](./network.md) 把浏览器中的 URL、状态码和耗时映射到网络链路。
5. 学习 [Nacos](./nacos.md) 和 [常用微服务工具](./microservice-tools.md)，理解服务发现、配置、限流和接口联调。
6. 再看 [微服务与消息系统](./distributed.md)，理解远程调用、消息、幂等和最终一致性。
7. 阅读 [设计模式](./patterns.md)，把代码中的工厂、代理、策略和事件映射到真实扩展点。

## 用一次接口请求串起各层

```text
浏览器 Network
  -> DNS / TCP / TLS / HTTP
  -> Nginx 或 API Gateway
  -> 服务发现与负载均衡
  -> Controller / Service
  -> 数据库或消息代理
  -> 响应、异步处理状态和服务日志
```

排错时记录 request URL、状态码、响应耗时、requestId/traceId 和业务 ID。不要只凭一个 502、超时或空列表推断具体根因；要确认失败发生在哪一跳，以及降级或重试是否改变了响应语义。

## 检查自己是否掌握

- 能区分 Git 工作区、暂存区和提交，并知道 `revert` 与 `reset` 的影响范围。
- 能从 Maven 依赖树找到某个类来自哪个依赖，并解释 `test`、`runtime` 等 scope。
- 能说明容器端口、宿主机端口、卷、网络和健康检查分别解决什么问题。
- 能从浏览器请求顺序解释 DNS、TCP、TLS、HTTP 和 CORS 的失败位置。
- 能解释服务发现只找到实例，不能保证实例调用成功。
- 能区分连接超时、响应超时、上游 deadline 和重试总时限。
- 能说明生产者确认、消费者 ACK、数据库提交和消息去重各自覆盖的范围。
- 能画出业务表、Outbox、消息代理、消费者幂等记录之间的事件流程。
- 能用 traceId 关联同步调用，并说明异步消息需要显式传递哪些追踪上下文。

当前项目的模块和接口路径见[项目与微服务地图](../project-map.md)。项目配置可能随分支和部署环境变化，实际排查要以当前代码、运行配置和日志为准。
